# VTOUR — публичная страница тура

Статическая страница вьювера 360°-тура. Без сборки и без npm — чистые
HTML/CSS/JS, открывается через любой статический веб-сервер.

## Запуск локально

Проще всего — открыть `web/index.html` двойным кликом прямо в браузере,
без сервера. Ничего запускать не нужно.

Технически: страница пытается получить `manifest.json`/`listing.json` и
`panorama.jpg` через `fetch()`, а браузер блокирует такие запросы к
локальным файлам (`file://`) из соображений безопасности. Поэтому рядом с
каждым `*.json` лежит его `*.js`-дубликат (`manifest.js`, `listing.js`) —
обычный `<script src>` браузер с `file://` грузить разрешает, и страница
сама на него переключается, если `fetch()` не сработал. Панорама в этом
случае грузится через обычный `<img>` вместо потокового `fetch()` — теряется
только точный процент прогресса (вместо него — индикатор "грузится"), само
изображение показывается так же.

На настоящем хостинге (http/https) `.js`-дубликаты не нужны — там `fetch()`
сразу работает и подтягивает `.json`. Если позже подключаешь свой реальный
экспорт из приложения (см. ниже) и хочешь тестировать его тоже через
`file://`, сгенерируй такие же `.js`-копии рядом с `manifest.json`/`listing.json`
(смотри `tours/demo/manifest.js` как образец: `window.__TOUR_MANIFEST__ = {...}`).

Если всё же нужен локальный сервер (например, чтобы отдавать реальный
прогресс загрузки панорамы):

```bash
cd web
python -m http.server 5500   # или: npx serve .
```

и открыть `http://localhost:5500`.

По умолчанию грузится тестовый тур `tours/demo` (две станции — ваши тестовые
фото). Чтобы открыть другой тур, добавь параметр в URL: `?tour=<имя-папки>`.

## Как подключить свой бандл из приложения

1. Экспортируй бандл в iOS-приложении (`tour_<uuid>.zip`) и распакуй его.
2. Скопируй распакованную папку целиком в `web/tours/<slug>/` — так, чтобы
   рядом лежали `manifest.json` и `stations/station_NN/panorama.jpg`.
   Формат один в один совпадает с тем, что пишет `BundleExporter.swift`
   (см. корневой `README.md`), никаких преобразований не нужно.
3. Рядом с `manifest.json` добавь `listing.json` — это данные объявления
   (цена, описание, характеристики, контакты риелтора), которых нет в
   бандле приложения — их вносит риелтор/будущая CMS. Смотри
   `tours/demo/listing.json` как образец формата. Если файла нет — страница
   покажет только то, что есть в `manifest.json` (заголовок, адрес, станции).
4. Открой `web/index.html?tour=<slug>` (двойным кликом, с этим параметром
   в адресной строке) или, если сервер уже запущен, `http://localhost:5500/?tour=<slug>`.

## Как строятся переходы между станциями

`manifest.json` не хранит граф "какая станция с какой соседствует" —
приложение его не считает. Страница сама соединяет каждую станцию с
несколькими ближайшими по прямой (`computeEdges` в `app.js`), без учёта
стен — `room.json` с геометрией комнаты пока не разбирается. Для точных
переходов (не "напролом" через стену) это стоит в будущем считать на
сервере с учётом планировки RoomPlan.

## Известные упрощения (MVP)

- Мини-план — это просто точки станций на пустой сетке, не реальные стены
  квартиры (нет парсинга `room.json`).
- Миниатюры в нижней панели — это те же панорамы станций (уменьшенные
  через CSS), отдельных превью-картинок бандл не отдаёт.
- Лоадер показывает прогресс реальной загрузки первой панорамы
  (`Content-Length` при первой загрузке); превью-заглушки на момент
  загрузки нет — сервер мог бы отдавать маленький blurred-preview прямо
  в манифесте для мгновенной отрисовки.
